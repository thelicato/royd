# AGENTS.md

## Project overview

The project is named **royd**.

royd is an Android runtime designed specifically for OCI containers. Its main goals are:

- Run Android directly in Docker, Podman, or another OCI-compatible runtime without QEMU or a guest kernel.
- Keep the default user experience as simple as `docker run` or `docker compose up`.
- Minimise host-specific setup by relying on modern Linux kernel facilities such as binderfs.
- Reduce Android memory usage so that useful Android instances can run on low-RAM hosts and many instances can share one host efficiently.
- Keep Android container images usable without any royd-specific host binary.
- Offer an optional Go CLI for convenience, diagnostics, and instance management without making it a runtime requirement.

royd is an independent AOSP-based implementation. Prior art is credited in `docs/acknowledgements.md`. External Android container integrations must not be build, source, runtime, image, manifest, patch, device-tree, or vendor-tree dependencies. royd should not depend on QEMU-based optimisation techniques.

## Core architecture

The OCI image is the primary product. A user must be able to run royd directly with Docker or Compose without installing a royd daemon, launcher, or host helper.

The intended runtime model is:

```text
Linux host kernel
  -> Docker / Podman / OCI runtime
    -> royd container
      -> private mount namespace
      -> private binderfs instance
      -> Android init as PID 1
      -> Android userspace
```

The container should create and manage its own binderfs instance where possible. Android should see the conventional Binder device paths:

```text
/dev/binder
/dev/hwbinder
/dev/vndbinder
```

The implementation should hide binderfs details from Android framework components and from the user.

royd must prefer modern Android and Linux interfaces. In particular:

- Prefer binderfs over statically pre-allocating many host Binder devices.
- Prefer `memfd` over ashmem.
- Prefer cgroup v2-aware memory management.
- Prefer PSI-aware `lmkd` behaviour.
- Avoid DKMS or kernel module compilation as part of the normal runtime path.
- Avoid requiring KVM or QEMU.

A host kernel without the required Binder support may be unsupported. Failure in that case should be immediate and clearly explained in container logs.

## Container behaviour

The expected primary interfaces are similar to:

```sh
docker run --privileged -v android-data:/data -p 5555:5555 ghcr.io/<owner>/royd:<tag>
```

and:

```sh
docker compose up -d
```

The exact image name and final runtime flags may change as implementation work progresses.

Android `/init` should remain PID 1 unless there is a strong technical reason to change this.

Container stdout and stderr should expose Android logs so that:

```sh
docker logs -f <container>
```

behaves like a useful `logcat` stream by default. Normal `adb logcat` access must continue to work independently.

Startup diagnostics should also be written to container logs. They should clearly report relevant host capabilities such as Binder support, binderfs setup, cgroup mode, graphics mode, and fatal compatibility problems.

## Android image goals

The Android image should be built for container workloads rather than treated as a stock emulator image with runtime debloating layered on top.

Where practical, unnecessary packages and services should be removed at build time instead of disabled after boot.

Areas to investigate include:

- `ro.config.low_ram=true` and related framework behaviour.
- PSI-based `lmkd` configuration.
- Cached and background process limits.
- Reduced display resolution and refresh rate profiles.
- Optional host GPU acceleration through `/dev/dri`.
- Efficient software rendering for hosts without GPU access.
- Removal or optionalisation of telephony, Bluetooth, NFC, printing, wallpapers, setup flows, camera support, location services, media components, and other features not required by a given image profile.
- Sharing immutable OCI layers and Linux page cache between instances.
- Efficient per-instance `/data` storage.

Memory targets must be benchmark-driven. Do not claim that a given RAM size is reliable until it has been tested with a defined workload.

## Optional CLI

An optional CLI named `royd` may be implemented in Go.

The CLI is a convenience layer only. Removing it must not remove any core runtime capability.

Possible commands include:

```text
royd doctor
royd run
royd ps
royd shell
royd logs
royd stop
royd rm
```

The CLI may help with:

- Host capability checks.
- Generating or executing Docker commands.
- Instance lifecycle management.
- ADB access.
- Log access.
- Multi-instance workflows.

Do not introduce a mandatory royd daemon or background host service without a compelling reason.

## Security direction

Initial development may use `--privileged` to establish a working baseline.

After the architecture is functional, investigate the minimum capabilities, devices, mounts, namespaces, and security policy required to remove or reduce privileged operation.

Do not allow security-hardening work to obscure or block early architectural validation, but document temporary privileges clearly.

## Development rules

These rules apply to every session and every contribution:

- Use British English in documentation, comments, user-facing text, and commit-related suggestions unless an external API or upstream project requires exact wording.
- Do not use em dashes. Use normal dashes, commas, colons, semicolons, or separate sentences instead.
- Do not add useless blank lines or excessive vertical spacing in documentation.
- Keep documentation concise, technical, and maintainable.
- Prefer simple designs with explicit dependencies over hidden host mutation.
- The OCI image is the primary interface. The optional CLI must never become mandatory for normal operation.
- Prefer capability detection over Linux distribution detection.
- Prefer upstream Linux and Android mechanisms over distro-specific workarounds.
- Avoid adding legacy compatibility code unless there is a demonstrated need and the maintenance cost is justified.
- Keep changes scoped to one meaningful task at a time. Prefer a cohesive small milestone over micro-tasks that change only one trivial file, while keeping each task reviewable and independently revertible.
- Stop after completing each atomic task. Summarise what changed, state which roadmap work was closed in the round, list the remaining roadmap tasks as a numbered list, distinguish repository implementation work from validation that requires real AOSP builds or external hosts, and suggest one Conventional Commit message. Do not continue to the next task until the user asks to proceed.
- Use Conventional Commits for commit suggestions, for example `docs: add project architecture guidelines`, `feat: add binderfs bootstrap`, or `test: add host capability checks`.
- Do not commit generated artefacts, build outputs, caches, credentials, secrets, or machine-specific files unless they are intentionally part of the project.
- Treat the work as a repository, not as isolated files. Preserve the full repository structure across tasks.
- After every completed atomic task, provide a ZIP archive containing the complete repository state and a `.patch` file containing only the changes made by that atomic task.
- The patch must be suitable for review and, where practical, application with standard Git tooling. Generate it relative to the repository state before the current atomic task.
- When changing runtime behaviour, add or update tests or reproducible validation steps where practical.
- When assumptions about Linux kernel or Android behaviour matter, prefer verifying them against current upstream documentation or source before implementation.

## Current decisions

- Development build workflow: the agent is authorised to perform required Android 15 baseline rebuilds, OCI packaging and local Docker import after scoped implementation, checks and atomic commits, then continue fresh runtime qualification without a user build hand-off. Use the existing Git identity, do not amend or push, and preserve generated evidence. Repository ZIPs and per-task delivery patches are waived; repository-owned AOSP source patches remain build inputs.
- Pinned Android versions: 8.0 through 17. Android 15 remains the default baseline until every version completes clean build and boot validation.
- Active runtime scope: prioritise Android 15 x86_64 with the standard graphical software profile in privileged Docker until scrcpy streaming is stable and recurring runtime errors are understood. Keep the measured resource-profile evidence, but defer any attempt to prove that performance mode is faster. Keep other versions, arm64, alternative profiles, host GPU and capability reduction configured, but defer their active validation while this baseline is improved.
- Performance direction: low-memory operation is one profile, not a permanent ceiling. Android 15 must also scale on hosts and containers with ample RAM and CPU, with resource-aware framework, Dalvik, `lmkd`, display and graphics policies rather than forcing the low-RAM baseline everywhere. Leading Android container interactive performance is a benchmark target, not a current claim. Comparisons must use the same host, Android version and architecture, renderer, display dimensions and frame rate, container limits, image state and named workload.
- CI model: `make ci` is the canonical lightweight repository suite. `make android-matrix-report` distinguishes configured Android metadata from resolved checks against locally synced AOSP trees. Missing trees are informational unless strict matrix mode is requested.
- Clean-build validation: use `make android-build-matrix` on dedicated build hosts. Results are generated under `.work/build-results`, are resumable by default, and must remain separate from runtime support claims.
- Runtime qualification: use `make runtime-qualification` on imported images. Persisted result format 4 evidence lives under `.work/runtime-results` and covers host, image, boot, health, runtime, security, graphics, log forwarding, ADB, Binder isolation, and a companion full Docker log/inspect evidence directory captured before container cleanup. A passing runtime qualification is evidence, not by itself a support claim.
- Android 15 restart validation: use `make runtime-restart-test` for fresh boot, Docker restart and recreation with the same disposable `/data` volume and pinned image ID. Require full runtime assertions and unchanged data checksum, durable global setting, Android ID and package UID in every phase. Retain per-phase Docker/runtime/persistence evidence and a result manifest before cleanup, including failures; never adopt existing resources or overwrite evidence. This does not qualify framework-only restarts, upgrades, host power loss or long soaks.
- Android 15 boot observation: the TLS runner waits for the delegated-cgroup init log through `wait-for-boot.sh`'s optional `ROYD_BOOT_WAIT_MARKER` before exec-based polling. A log marker only permits polling, never establishes controller readiness. Keep full memory-controller assertions.
- Android 15 capture validation: the Docker-only host assertion runs its repository-owned shell helper inside Android, records a unique non-overwriting temporary MP4 in user 0's shared Movies directory, waits for matching MediaStore video metadata and verifies deletion of its exact file/row and private name reservation. screenrecord always broadcasts a media scan, so private-path captures and immediate deletion create invalid test requests. Set only the child Java CLI's standard Android paths and generated boot/dex2oat classpaths, reading them as data rather than executing the init export file. Bound commands and the overall capture, preserve real H.264 recording and reject test-path scan errors, provider failures, incomplete metadata and failed cleanup. Never filter generic media warnings, change storage permissions or require host ADB/media tools. This is a host validation change, not an Android image input or general shared-storage qualification.
- Android 15 memory-delegation policy: only with `ROYD_CONTAINER=1`, the SELinux enforcement interface absent with `ENOENT`, and the existing unified royd hierarchy gate, retry an `EBUSY` memory-controller enable at 50 ms intervals against a 10-second monotonic deadline. An early external OCI exec may temporarily occupy the namespace-root cgroup. Never move external processes, relax kernel domain constraints or change root ownership. Preserve immediate failure for every other error, return setup failure without a success marker on exhaustion, and retain stock handling outside the gate. Stock `CgroupSetup` logs individual setup failures and continues, so this is not a fatal-boot guarantee. `make runtime-cgroup-delegation-test` uses diagnostic-only entrypoint delays to prove transient recovery and bounded persistent failure, with full runtime assertions on the recovered container. General indefinite early-exec concurrency remains unqualified.
- Android 15 framework-restart validation: `make runtime-framework-restart-test` uses the restart runner's separate framework mode and format-2 manifest. Require observed readiness reset/recovery, replacement zygote/SystemServer PIDs, unchanged Docker identity/start time, full post-restart assertions and unchanged persisted state. Require a local Unix-socket Docker engine, verified native init/SystemSuspend trace attachments through recovery/workload, the bounded init power-skip marker and no traced opens/writes to host power controls. Never reset readiness from the test, trace Java descendants or restart an unqualified old image to probe host power safety. This remains distinct from long soaks and reference-host support review.
- Android 15 application HTTP validation: use `make runtime-network-http-test` for a controlled literal-IPv4 WebView page and JavaScript callback on the local Docker bridge, with non-root app identity and full pre/post runtime checks. The optional host-only Go fixture serves no files and adds no runtime dependency. Keep DNS/TLS explicitly untested and retain Android's reported default-network state independently; OCI packet transport without a framework default network is not complete application Internet support. Preserve OCI ownership of `eth0` and do not fabricate capabilities or weaken application security policy.
- Android 15 application DNS validation: use `make runtime-network-dns-test` to compare direct UDP DNS and nonce HTTP controls with the normal app resolver and ConnectivityManager state/callbacks under the same ordinary UID. The disposable test APK uses only normal network permissions and AOSP's public test key, not a platform/shared UID. Bind a non-recursive single-name DNS fixture only to the local private Docker bridge and pass it through container-local `--dns`; never change host resolver settings. Retain split transport, DNS, framework and full post-workload runtime results, including failures. Docker's resolver file alone does not configure Android's per-network resolver. Missing framework networks and resolver configuration are functional blockers, not warnings to suppress; preserve OCI interface ownership and do not fabricate validation capabilities.
- Android 15 public HTTPS validation: use `make runtime-network-tls-test` with inherited Docker DNS and an ordinary test UID. Use unchanged platform HTTPS trust/hostname verification, reject redirects, and require public IPv4 DNS, expected HTTP status, peer/cipher/body evidence, default-network callbacks and full pre/post runtime checks. An ephemeral self-signed server binds only to the owned private Docker gateway, has a matching IP identity, and must fail with a certificate-caused SSL handshake error without receiving HTTP. Never install its certificate, weaken verification, change proxy/private-DNS settings or alter host networking/time. Retain format-1 evidence, including failures and unchanged OCI configuration. Repeat with `ROYD_NETWORK_TLS_NETWORK_MODE=private` for embedded DNS. Public endpoints are external availability dependencies of this optional test, not CI or normal Android startup dependencies; a failure is not evidence of certificate rejection without the exact cause.
- Android 15 WebView HTTPS validation: `make runtime-network-webview-tls-test` enables the TLS runner's optional WebView mode without changing native HTTPS controls. Require a matching committed public document, visual-state callback, complete secure DOM with expected title/h1, provider/version and certificate identity, followed by cancellation of the exact private control's `SSL_UNTRUSTED` error. A generic transport/handshake failure is not certificate-rejection proof. Never expose a native JavaScript bridge, proceed past SSL errors, install trust material or change platform networking/security policy. Format-2 evidence additionally records both WebView statuses and the declared page/title; retain full independent pre/post runtime and unchanged OCI checks. The default public page is IANA's `https://www.iana.org/help/example-domains` with title/h1 `Example Domains`, replacing example.com's changed markup without relaxing document assertions. This remains an optional external availability/content dependency, not an image or startup dependency or a service guarantee. Other pages, trusted-chain hostname/expiry failures and general browser compatibility remain separate validation.
- Reference-host kernel evidence: use `make runtime-kernel-evidence` before or alongside real-host validation. Evidence format 1 records live Binder/cgroup/PSI/LSM/DRM state plus the versioned `runtime/kernel/config-contract.tsv` Kconfig set when readable. Reference-host bundle format 4 requires this evidence and its contract digest, and requires retained scrcpy stability evidence for Android 15 graphical qualification. The minimum known-good kernel configuration remains an external-validation item until the collected Android boot evidence is reviewed.
- Runtime engine boundary: rootful Docker Engine and Docker Compose v2 are the configured primary interfaces. Podman rootful is a documented compatibility candidate, not a qualified substitute. The packaged runtime tar is a root-filesystem archive and the current image import, inspect, security evidence, Compose, and qualification paths are Docker-specific. Rootless operation has been evaluated as an unqualified compatibility candidate: binderfs supports user-namespace mounts, and `make runtime-rootless-probe` checks host prerequisites without an Android image, but real Android boot and qualification remain external validation.

The following decisions are currently agreed:

- Project name: `royd`.
- Primary runtime: OCI container image.
- Primary user experience: plain Docker or Docker Compose.
- No mandatory royd host binary, daemon, or bootstrap service.
- Optional CLI: Go. Keep the implementation small, local-first, transparent about Docker operations, and limited to convenience commands and lightweight host checks until runtime validation justifies more automation.
- Binder strategy: mount royd's private binderfs instance at `/dev/royd-binderfs`, allocate its Binder devices there, and expose them at `/dev/binder`, `/dev/hwbinder`, and `/dev/vndbinder`. Keep this mount separate from Android's own `/dev/binderfs` mount so Android init cannot hide royd's allocated devices.
- Android 15 Binder security-context policy: when the existing explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, `servicemanager` must not request sender SIDs or register the Binder context manager with `FLAT_BINDER_FLAG_TXN_SECURITY_CTX`. Preserve the normal Binder security-context request for every other Android run.
- Android 15 vold SELinux policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, tolerate only the unavailable SELinux labelling operations needed for user-storage directory preparation. Preserve stock fatal handling for every other vold error and Android environment.
- Android 15 SystemSuspend policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, do not open the host's `/sys/power/wakeup_count`, `/sys/power/state`, `/sys/power/wake_lock` or `/sys/power/wake_unlock`. Use SystemSuspend's upstream blocking socketpair fallback and in-process native wake-lock counter, retain Binder tokens and statistics, and omit the host-global zygote wake-lock release. Under the same gate, init must skip writes to those four exact paths, including zygote restart actions, without changing other init writes or their error handling. Preserve stock power-file and kernel-wake-lock handling in every other Android environment.
- Android 15 Keystore2 policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active and Binder supplies no caller SID, permit only UID 1000 `unlock` and `change_user` service operations plus `delete`, `get_info`, `rebind`, `update`, and `use` for LockSettings SELinux namespace 103. Do not provide a grant fallback or permit any other caller, namespace, or permission. Suppress Keystore2 Binder SID requests only under the same gate, and preserve stock Binder SID and SELinux enforcement everywhere else.
- Android 15 KeyMint baseline: install AOSP's `android.hardware.security.keymint-service` so Keystore2 has its mandatory default KeyMint instance. This is AOSP's explicitly insecure, in-process software reference implementation and does not provide hardware-backed key protection. The module owns its early-HAL init rule, hardware-keystore permission and KeyMint, SharedSecret and SecureClock VINTF fragments; do not duplicate those declarations in royd's central device manifest.
- Android 15 installer FRP policy: only under the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate, with `ro.frp.pst` empty and no published persistent-data-block service, omit PackageInstallerSession's optional manager lookup and use its existing null-manager result. If a backing store is configured or a service is published, preserve stock lookup, active-FRP checks, caller denial and failures. Preserve the legacy secure-FRP setting branch, session ownership/transfer checks and stock behaviour outside the gate. Never disable FRP globally or suppress post-boot missing-service diagnostics. Rebuilt-image validation installs the ordinary test APK and requires full post-workload runtime checks; the independent DNS gap may still fail overall DNS qualification.
- Android 15 Zygote app-data isolation policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, retain the stock tmpfs and per-package bind-mount isolation but skip copying and reapplying unavailable SELinux file contexts. Preserve stock app-data isolation and labelling in every other Android environment.
- Android 15 Zygote system_server policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, skip only the otherwise unavailable `selinux_android_setcon` transition to the system_server domain. Preserve the stock process-context setup and fatal transition handling in every other Android environment.
- Android 15 kernel-config visibility policy: when `LoadKernelConfigs` fails under the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate, conservatively report `CONFIG_VMAP_STACK` as unset because the container cannot read the host's `/proc/config.gz`. Preserve the stock kernel-config lookup and fatal failure handling in every other Android environment.
- Android 15 Installd app-data policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, skip only the lazy SELinux context comparison for an existing app-data directory because its file-context xattr is unavailable. Preserve new-directory restorecon, interrupted-restorecon recovery, directory ownership and modes, and all stock labelling behaviour in every other Android environment.
- Android 15 package-list SELinux policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, write `/data/system/packages.list` without looking up or setting its unavailable SELinux file-creation context. Preserve the package-list contents and atomic writer, and preserve all stock context handling in every other Android environment.
- Android 15 CPU monitor policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active and the host exposes no CPU frequency policy directories, do not start Android's debug-only CPU monitor. Preserve stock monitor startup and fatal diagnostics when policies exist and in every other Android environment.
- Android 15 CPU-frequency residency policy: under the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate, report a missing `KernelCpuSpeedReader` residency interface once per reader only when opening it throws `FileNotFoundException` with a direct `ErrnoException(ENOENT)` cause. Keep every read attempt, stock zero-array error fallback, delta history, hotplug handling and StrictMode restoration unchanged so later availability is detected. Preserve all other errors, parsing failures and behaviour outside the gate. Missing residency is unavailable accounting, not measured zero CPU use or qualified CPU energy attribution; independent CPU-time collection remains enabled.
- Android 15 Binder-freezer policy: under the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate, disable cached-app freezing and reject direct Freezer Binder freeze/status operations before native calls. Older Binder drivers match host-global PIDs across Binder contexts, so container PIDs can fail or target unrelated processes. Skip only ProcessList's Binder-freezing phase during package termination; preserve private UID-cgroup freezing, synchronous process removal, cleanup and all stock behaviour outside the gate. Emit the mode once per framework process. Namespace-safe Binder freezing remains unqualified even on newer hosts, and must not be enabled by a kernel-version guess, host-PID translation or a single successful status probe. Runtime assertions require disabled cached-app freezing, zero frozen apps and the mode marker after the workload, and reject freezer-operation failures. Graphical qualification also requires a real application force-stop, absence of its old process, a fresh same-UID process after relaunch, a removed or thawed UID cgroup and a stable SystemServer.
- Android 15 ActivityManager PSI policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, use proportionally scaled 2-second PSI windows for ActivityManager's low-memory detector because upstream Linux permits unprivileged PSI triggers only at 2-second multiples. Preserve the detector's stock pressure ratios, retain `lmkd`'s independent PSI monitoring and fallbacks, and preserve stock 1-second windows in every other Android environment.
- Android 15 resource-profile policy: keep `low-memory` as the runtime default, with low-RAM framework behaviour and the existing 512 MB-class Dalvik heap. Provide an explicit `performance` mode that selects normal-RAM framework behaviour and AOSP's 2 GB phone Dalvik heap before Android publishes boot properties. Keep per-app memcg enabled explicitly in both modes so the delegated cgroup-v2 `memory.low` policy does not disappear when normal-RAM behaviour is selected. Load the generated property file only under the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate, reject performance mode on other Android versions, and record the selected mode in runtime evidence. Compare the two modes by alternating fresh-data repetitions under identical CPU, memory, display and graphics limits, recording boot-to-Home, application launch, a repeated Settings, DocumentsUI and Home workload, frame timing, encoder health, cgroup CPU and memory evidence. Summarise repeated measurements with medians and ranges, and retain phase-labelled per-process RSS evidence for memory outliers. Do not describe performance mode as faster until the repeated measurements exceed run-to-run variation.
- Android 15 ART overlay policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, classify the OCI root overlay as the system partition for ART artefact placement. This preserves ART's conservative global dalvik-cache result without throwing one service exception per system APK when there is no physical system-partition mount beneath the overlay. Restrict the exception to the root overlay, retain normal writable `/data` classification, and preserve stock overlay-remount handling in every other Android environment.
- Android 15 metadata fs-verity policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, skip the system-server `FileIntegrity` helper's best-effort fs-verity protection for redundant package, permission, role, user and shortcut metadata because the container storage does not support the enabling ioctl. Preserve atomic and reserve-copy writes, leave APK, font and app-facing fs-verity paths unchanged, and preserve all stock fs-verity behaviour in every other Android environment.
- Android 15 legacy cgroup-profile policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, omit only task-profile `JoinCgroup` actions whose configured cgroup-v1 controller root has no `cgroup.procs` interface and reports `ENOENT`. Do not treat the mount-point directory alone as proof that the hierarchy is mounted. Preserve timer slack, scheduler and other profile actions, keep the delegated cgroup-v2 memory policy unchanged, use a legacy controller if it is actually mounted, and preserve all stock task-profile behaviour in every other Android environment.
- Android 15 StatsD policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, disable statsd's Binder caller-SID request so the driver can deliver transactions without an unavailable security context. Preserve every StatsService UID, permission and SID check, including denial of non-root SID-protected subscription calls without a SID. Preserve the stock SID request in every other Android environment. Runtime qualification requires a real statsd Binder metadata response and rejects stats-puller registration failures.
- Android 15 memory-event policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, do not start ActivityManager's optional OOM event listener or initialise lmkd's optional BPF memory-event listener. These upstream tracepoints are host-global and have no container filter. Select lmkd's stock vmstat reclaim fallback, preserve its PSI monitoring, process controls and kill reporting, and preserve ActivityManager's independent low-memory detector. Do not grant host tracing privileges or change host perf sysctls. Kernel OOM event attribution and tracepoint-based direct-reclaim timing remain unavailable until a container-scoped implementation is validated. Preserve stock memory-event behaviour in every other Android environment.
- Android 15 recents cleanup policy: when the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate is active, treat a lazily uncreated recents task or icon directory as empty only when listing fails, `lstat` reports `ENOENT`, and its user-storage parent is a directory. Retain diagnostics for unavailable user storage, dangling symlinks and every other listing failure. Recheck on every cleanup so later task and icon writes remain visible, retain stock atomic persistence and obsolete-file deletion, and emit one bounded container marker. Preserve stock behaviour in every other Android environment.
- Android 15 Settings hardware policy: under the explicit `ROYD_CONTAINER=1` plus kernel-SELinux-disabled gate, do not resolve Wi-Fi for the device-name controller when the product lacks the Wi-Fi feature, and omit only its hotspot-SSID rename operation. Keep the global device name and Bluetooth handling unchanged. Under the same gate and absent Wi-Fi feature, omit the About-phone Wi-Fi MAC controller's manager lookup and retain its existing unavailable state without fabricating an address or changing lifecycle handling. Skip SettingsLib's USB charger-warning service lookup only when neither USB-host nor USB-accessory hardware is advertised and Android is not an emulator. Preserve the secure warning setting, supported-hardware lookups and failures, all post-boot framework WTF reporting and stock behaviour outside the gate. Graphical runtime assertions open About phone, check Settings and system-server stability and recheck missing-service WTFs after the workload. Scrcpy evidence format 2 includes full post-workload runtime assertions and their log, and retains failed-result evidence before cleanup.
- Android 15 GPU-memory tracing policy: when `ROYD_CONTAINER=1` and the kernel SELinux enforcement interface is absent with `ENOENT`, do not initialise GpuService's optional GPU-memory BPF collector or its Perfetto source. The tracepoint attachment is system-wide and the collector does not filter by container. Keep the existing joinable initialisation thread, report GPU-memory tracing as explicitly unavailable rather than zero, and preserve GPU driver statistics, the separate GPU-work policy, rendering and Binder dump permissions. Preserve stock initialisation and dumps when the SELinux interface exists or its probe fails with any other error. Runtime qualification requires the bounded skip marker, the explicit unavailable dump and real graphical driver statistics, and rejects the former attachment/initialisation diagnostics.
- Android 15 GPU-work tracing policy: under the same explicit container gate with the SELinux enforcement interface absent with `ENOENT`, do not initialise the optional GPU-work BPF collector, wait for its tracepoint or register its statsd puller. The system-wide tracepoint identifies only host GPU IDs and UIDs, not containers. Report GPU-work accounting as explicitly unavailable rather than zero; preserve rendering, driver statistics, memory-tracing policy, joinable service threads and stock behaviour outside the gate. Runtime qualification requires the bounded GPU-work skip marker and unavailable dump and rejects the former collector failures. Container-scoped GPU accounting remains unimplemented.
- Android 15 ServiceManager blocking policy: backport the upstream framework fix that marks ServiceManager's native `IServiceManager` proxy as safe for its required synchronous calls, matching the existing treatment of the legacy context-manager proxy. Preserve `SystemServer`'s blocking-call warnings for every other Binder proxy and preserve all service lookup semantics.
