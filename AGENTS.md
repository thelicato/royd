# AGENTS.md

## Project and architecture

royd is an independent AOSP-based Android runtime for OCI containers. The OCI image is the primary product. Plain Docker and Compose must work without a royd daemon, launcher or host helper. The optional Go CLI is a convenience layer. Credit prior art in [acknowledgements](docs/acknowledgements.md); external Android container integrations must never become product build, source, runtime, manifest, patch, device-tree or vendor dependencies.

Android shares the host Linux kernel, with private mount, Binder and network state. Do not require QEMU, KVM, DKMS or normal-path module compilation. Prefer binderfs, sealed memfd, cgroup v2 and PSI. Unsupported Binder hosts must fail early with a clear diagnostic. The container creates its own Binder devices and exposes `/dev/binder`, `/dev/hwbinder` and `/dev/vndbinder`. Keep the private allocation mount at `/dev/royd-binderfs` separate from Android's `/dev/binderfs`.

Android `/init` remains PID 1. The entrypoint validates configuration, prepares files and immediately execs init. Android logs and startup diagnostics go to OCI stdout/stderr; `docker logs` and independent `adb logcat` must both work. No logging supervisor or mandatory host service.

Read [architecture](docs/architecture.md), [hardware contract](docs/hardware-contract.md), [runtime](docs/runtime.md), [security](docs/security.md) and the relevant source before changing an interface.

## Active scope and acceptance

The active baseline is Android 15 x86_64, standard graphical, software rendering, low-memory resource mode, privileged rootful Docker and one OCI-owned IPv4 `eth0`. A comparable phone AVD is the feature ceiling. Optional printing, Bluetooth, NFC, camera, telephony and other peripherals may remain absent; do not add them merely to remove diagnostics. Prioritise boot, ordinary apps, graphics/streaming, networking and persistent data.

Historical WebView/Launcher focus ANRs and startup pre-watchdogs have incomplete causal evidence. Their exact causes remain unknown and are accepted as a documented historical limitation, not a prerequisite for final-candidate acceptance. Do not describe them as fixed. Preserve the failures, diagnostics and attribution limits. Every final-candidate ANR, input-timeout, pre-watchdog and other existing runtime rejection remains mandatory, including before and after workloads, and a new failure requires diagnosis. Never increase responsiveness deadlines or change credential durability to obtain acceptance. See [known limitations](docs/known-limitations.md).

Other Android versions, arm64, alternative profiles, host GPU, rootless/alternative engines, minimum-capability promotion and performance-mode speed claims are deferred. They remain configured or experimental as documented. No supported RAM minimum, performance advantage, continuous visual-quality guarantee or broad compatibility claim follows from local passes.

## Build and image contracts

- Fetch only pinned AOSP through the normal dependency path. All royd products, vendor code, helpers, init rules, profiles and patches live here. Do not inherit emulator product bundles or `emulator_vendor.mk`.
- Android 8.0 through 17 have pinned configurations; Android 15 is the development baseline. `x86_64` and `arm64` use owned `royd_x86_64`/`royd_arm64` products with `userdebug`. Android 8.0 through 10 use the legacy Ubuntu 18.04/JDK8 builder and compatibility path; modern releases use the modern builder. Configuration is not support.
- Every build applies/checks repository patches before compilation, including incremental builds after append-only patch additions. Install owned device/vendor definitions through repository scripts. Do not hand-edit applied AOSP source or change an applied patch without controlled reverse/reapplication and verification.
- Keep no-kernel/no-bootloader mode, required ext4 partitions and copy-out paths explicit in `android/build-contract.env`. Validate resolved AOSP configuration before compilation. Preserve old symbols and necessary evidence before replacing clean outputs.
- Package ramdisk plus required system/vendor/system_ext/product partitions and optional odm as one OCI root filesystem. Materialise `/etc` where Docker replaces Android's symlink, with regular `cgroups.json` and `task_profiles.json`; do not change Docker's network files.
- Record immutable `/royd-release`, canonical tuple tags, archive checksum and profile-policy identity. Verify the sidecar digest before import. `royd:dev` and `royd:dev-minimal` are local aliases. Package-policy changes run installclean. The standard/minimal policy and protected core package lists remain explicit.
- Keep [building](docs/building.md), [build validation](docs/build-validation.md), [Android versions](docs/android-versions.md) and [image profiles](docs/image-profiles.md) consistent with source. `make ci` is the repository suite; matrix reports distinguish configured metadata from resolved/build/runtime evidence. Missing source trees are informational unless strict mode is requested.

## Security and host ownership

All Android 15 container exceptions require the exact gate specified in their source, normally `ROYD_CONTAINER=1` and a SELinux enforcement-interface probe failing with `ENOENT`. Other errors must not activate an exception. Preserve stock behaviour outside the gate, all unrelated errors, permissions, atomic writers, ownership and modes. Optional hardware guards additionally require the relevant feature to be absent. Never replace these gates with an Android-version or distribution guess.

- SystemSuspend uses blocking socketpair fallback and in-process wake locks. Init and Zygote must not access the host-global `/sys/power/state`, `wakeup_count`, `wake_lock` or `wake_unlock` controls under the gate. Preserve wake-lock tokens/statistics and native power-control trace validation.
- Framework wall-clock setters skip host wall-clock/RTC writes and do not claim unapplied confidence updates; AlarmManager returns false with permissions intact. Keep reads, elapsed time, timezone and independent confidence updates. Test positive setters only in mocks; live API testing may use only the JNI-proven non-positive invalid argument.
- Watchdog must not open `/proc/sysrq-trigger` under the gate. Keep timeout/checker policy, pauses, monitors, process/DropBox dumps and termination unchanged. Emit bounded on-demand skip diagnostics and the exact blocked subject/checker times; a recorded start precedes the stock queue-post call. Do not force an overdue watchdog on the shared host.
- Do not initialise host-global GPU memory/work or OOM/reclaim tracepoint collectors. Report unavailable data explicitly, preserve rendering/driver statistics, lmkd's vmstat fallback and independent PSI monitoring. Do not grant host tracing privileges or change perf sysctls to satisfy a collector.
- Do not write host-global BPF JIT/unprivileged-BPF preferences or legacy UID CPU cleanup controls. Preserve independent BPF accounting and local UID-history retirement. Missing CPU residency is unavailable energy accounting, not measured zero; keep read retries and non-ENOENT failures.
- Vold's FUSE aborts are restricted to connections represented by mounts in its own namespace. Recreate the missing first-stage `/mnt` tmpfs only under its existing gate. Preserve user-storage ownership, permissions and all non-context failures.
- Keep app-data tmpfs/bind isolation. Omit only unavailable SELinux operations in Zygote/vold/installd/package-list paths under their exact gates. Binder SID exceptions retain service caller checks. Keystore's no-SID fallback is restricted to UID1000's documented LockSettings operations/namespace103, with no grant fallback. Software reference KeyMint is explicitly insecure and not hardware-backed.
- Binder freezing is disabled because PID-namespace safety is unqualified. Keep cached-app freezing disabled and reject direct Binder freeze/status before native calls. Retain private UID-cgroup freezing and synchronous process removal. Never enable it from a version guess, host-PID translation or one successful probe.
- Privileged rootful Docker is the baseline, not a security boundary against hostile root. Capability reduction uses the versioned inventory and real-host evidence. Do not promote experimental mode to a supported minimum from static tests.
- Default development ADB has authentication disabled. Publish loopback-only; required-auth mode selects stock key authentication, fails closed and accepts only public-key mounts. TCP authentication is not encryption; use SSH forwarding remotely. Never expose private keys or silently downgrade authentication.

## Runtime integration

- Delegate only `/sys/fs/cgroup/royd` to Android's system UID. Leave Docker's root ownership unchanged and keep the delegated root process-free by moving init into its leaf. Use cgroup-v2 memory and correct namespace-absolute path normalisation. Retry only controller-enable `EBUSY` against the existing ten-second monotonic deadline; never move external processes. Setup errors remain visible.
- Skip only unavailable legacy `JoinCgroup` actions whose configured `cgroup.procs` interface reports `ENOENT`. A mount-point directory alone is insufficient. Preserve scheduler, timer slack and all other actions; use a mounted legacy controller normally.
- Select sealed memfd after stock property reset. Preserve the scoped mediaextractor seccomp additions, required-policy failure, non-executable flags/sizing/seals, stock vendor policy, no-new-privileges and all other sandbox restrictions. See [media sandbox](docs/media-sandbox.md).
- Trigger stock `nonencrypted` for fstab-less boot. Report `/data` filesystem capacity unrounded without using physical block-device APIs or claiming per-instance allocation. Keep free/cache/quota accounting unchanged.
- Classify only the OCI root overlay as ART's system partition. Metadata fs-verity exceptions cover only the documented redundant system-server metadata, preserving reserve-copy/atomic writes and APK/font/app paths. Lazily absent recents directories require exact ENOENT plus a valid user-storage parent; other failures stay visible.
- Framework readiness resets at SystemServer construction and becomes ready only after successful boot-completed callbacks. Do not replace it with persistent `sys.boot_completed`. Pre-publication manager/DropBox handling must retain lookup results, initialisation, later persistence and post-ready WTF reporting.
- Defer AudioPolicyService ActivityManager/sensor-privacy registration until publication using existing conservative fallback and retries. Keep Binder work outside the audio-policy mutex. The native ServiceManager synchronous-call exemption must not disable other Binder blocking warnings.
- Keep the owned example Health/Power HALs and stub AIDL Audio APEX. Their modules own VINTF/init declarations. Do not duplicate fragments or claim physical hardware capability. The software Codec2 store supplies H.264/Opus and uses the local AIDL input-surface path and gralloc BLOB pools.
- Settings must honour absent features in indexing and ordinary/direct navigation. Preserve general controls, dock callbacks, inherited exclusions/restrictions, supported-hardware failures and post-boot diagnostics. Use the SDK35 static resource overlay only for the declared unavailable product capabilities. Printing stays absent with a localised unavailable fallback. Do not catch arbitrary provider exceptions or advertise hardware to make indexing pass.
- Keep Telecom manifest and dexpreopt class-loader context consistent with boot-classpath IKE exclusion. Preserve compiler filters, compile dependencies and ART verification.

## Graphics and memory

Android 15 uses ANGLE over SwiftShader Vulkan (`vulkan.pastel`), owned memfd allocation, stable-C mapper V5 and composer3 with stable-AIDL release handling. Other configured releases retain their separately documented legacy graphics path. Software rendering needs no `/dev/dri`; experimental Mesa/minigbm host-GPU backends require explicit DRM access and real-driver qualification.

- Client-only composition has no physical scan-out timestamp: use `PRESENT_FENCE_IS_NOT_RELIABLE`, no fabricated fence or EDID, and preserve genuine errors. Vulkan presentation submits binary-semaphore waits once per batch under its x86_64/SwiftShader/container gate, preserving synchronous queue drain and whole-batch errors. Require the real single/two-swapchain pending-producer/pixel controls after relevant changes.
- Synthetic vsync uses steady-clock phase deadlines, skips missed ticks and preserves lifecycle/callback dispatch outside locks. Configured cadence is not achieved throughput. Disable eager software shader priming while retaining on-demand compilation and other backends.
- Limit only the automatic low-RAM x86_64 software Vulkan worker pool to min(logical CPUs, four, successful positive affinity). Probe failure retains the four-worker cap. Preserve explicit ThreadCount, performance mode, other platforms, floating-point setup and rendering semantics.
- Publish logical DPI before boot properties; validate and canonicalise display input with existing bounded ranges. The complete configuration reader rejects unknown/duplicate fields, NULs, truncation and read/close errors before replacing defaults. Resource-profile metadata is not display policy.
- Default display is 540x960, 240dpi, 30fps. Compact/tablet and headless profiles retain their documented scope. Default low-memory mode enables low-RAM behaviour, the 512MB-class Dalvik heap and PSI-based lmkd. Performance mode selects normal-RAM/2GB-phone heap before publication; both retain per-app memcg. Do not claim a speed advantage without repeated matched measurements.
- ActivityManager PSI uses proportionally scaled two-second windows under its exact gate; retain independent lmkd monitoring. Memory targets need named workload, host/image/profile/policy identity, repeated boots and resource evidence. A successful idle boot is not a supported RAM minimum.

## Networking

Read [network quotas and alerts](docs/network-quotas.md) and the actual source/tests before changing accounting or policy. The first scope is one OCI-owned IPv4 `eth0` and IPv4 DNS, including Docker embedded DNS. IPv6-only, multi-NIC/default, VPN/private-DNS and broader forwarding remain separately unqualified.

- The read-only NetworkAgent publisher observes actual addresses/main routes/resolvers, offers Ethernet transport without advertising Ethernet hardware, and withdraws on missing/ambiguous state. ConnectivityService owns per-network configuration. Never run IpClient/DHCP, provision OCI state, force validation/unmetered capabilities or bypass normal network selection. The priority31999 main fallback preserves earlier Android policies.
- Preserve unavailable legacy iptables diagnostics, no host module loading and stock failures outside the gate. Only strictly inactive unadvertised tether hardware may skip stop/lookups. Never exempt active/pending requests or weaken background policy.
- Metered UID denial/Data Saver uses the private cgroup-BPF selector with real packet enforcement. Keep system/loopback exemptions, penalty-before-happy-box precedence, unknown-selector fail-closed handling, real map-write errors and caller permissions. A getter/map change is not denial proof.
- TCX interface accounting is private, independently verified and ordered before quota enforcement. Count IP bytes with supported segmentation headers, not link-layer bytes or UID-only totals. Reject foreign/stale pins, replacement interfaces, missing attachments and sticky errors. Retain counters/maps across netd/framework restarts; never replace qdiscs or unowned links.
- UID recorder rotation uses a real RCU grace period: only after PF_KEY EAFNOSUPPORT, create/close an unbound protocol-zero AF_PACKET datagram socket. Preflight precedes selector rotation and the post-swap barrier precedes inactive-map reads/clears. Propagate all failures. Never substitute frozen-selector success, sleeps or packet capture. Public integer NetworkStats APIs do not support Ethernet; keep normal-app other-UID denial.
- One non-per-CPU, non-LRU, NO_PREALLOC quota value owns the shared RX/TX budget. Atomic CAS admits only a complete fitting skb/GSO aggregate; crossing, bounded contention and invalid active packets fail closed visibly. Replace whole RCU-retired entries, preserve generation semantics and existing budgets on restart, and acknowledge only successful native updates.
- Global alerts sample private attempted IP bytes; associated alerts sample a separate admitted-byte counter. Neither sampler enforces a quota. Use positive bounded thresholds, fresh baselines, verified identities, nominal250ms sampling, real listener receipts and sticky faults. Extra non-loopback interfaces must not be silently omitted.
- Exhaustion feedback observes acknowledged quota generations and emits the existing eth0 event once. Start observers before acknowledging installation, preserve state on failed writes/removals, cancel uncommitted old events and release backend locks before Binder callbacks. Already committed delivery cannot be recalled. Old failure must not fault a replacement.
- Gated positive eth0 framework updates retain enforcement and use the acknowledged native atomic setter under existing NMS locks/permissions. Keep explicit removal, invalid/sentinel semantics, provider updates and prior bookkeeping on failed writes.
- Ethernet usage registration and template dispatch enter the unchanged policy callback/readiness/lock body. Preserve public type mappings, stock Mobile/Wi-Fi registrations, executor, thresholds, errors and outside-gate adapter. Before real usage readiness, only an active cycled unsnoozed gated eth0 limit uses the conservative one-byte allowance. Real callback recovery must permit the calculated allowance; never grant the full finite limit from unready zero usage.
- Netd owns listener registrations. Recovery tests must observe real old Binder death, empty new registration and explicit fresh-client re-registration. Do not claim automatic old-listener survival, continuous enforcement through restart windows or unflushed crash durability.

- Comparator measurements require a pinned independently qualified image and actual build/renderer/configuration parity, fresh matched resources and at least five alternating repetitions. Static strings/build IDs are insufficient. An external image requesting global pid/perf/clock changes is not cleared for privileged execution on the shared host: use a disposable separate kernel or a separately reviewed common containment policy. Preserve failures and mark absent metrics unmeasured. Never add comparator code/images to product dependencies.
