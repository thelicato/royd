# Android 15 container network quotas and alerts

The Android 15 backend implements private interface IP accounting, packet-path shared quotas, sampled global/associated alerts, hard-limit feedback and framework policy recovery. Dedicated local fixtures cover these paths; final clean-candidate acceptance remains pending. The scope is one OCI-owned IPv4 `eth0`, privileged rootful Docker and the declared host capabilities. See [known limitations](known-limitations.md#networking-and-storage) and [the completion checklist](android15-completion.md).

## Established source boundary

The pinned [netd BandwidthController](https://android.googlesource.com/platform/system/netd/+/8542734a0dd1db395a4d42aae09c37f3c3c3e7a1/server/BandwidthController.cpp) installs legacy filter/quota rules. Fresh logs show filter-table initialisation failing before quota-extension availability can be established. `setGlobalAlert` nevertheless records the requested size; a later call therefore updates the nonexistent `/proc/net/xt_quota/globalAlert` entry. An absent proc entry is a consequence of failed setup, not evidence that normal routing or all UID accounting fails. Failed installation must not become successful backend state.

In pinned Connectivity commit `64cd443febd3ee0fd5c90b47089d82b96850c1e9`:

- [NetworkStatsService](https://android.googlesource.com/platform/packages/modules/Connectivity/+/64cd443febd3ee0fd5c90b47089d82b96850c1e9/service-t/src/com/android/server/net/NetworkStatsService.java) registers a global alert, receives `onQuotaLimitReached`, schedules a statistics poll and rearms the alert. Statistics-provider notifications remain a separate part of registration.
- [netd.c](https://android.googlesource.com/platform/packages/modules/Connectivity/+/64cd443febd3ee0fd5c90b47089d82b96850c1e9/bpf/progs/netd.c) updates UID maps in its cgroup packet path. Interface statistics have separate xt_bpf/tc update sites. A working UID map is not proof of working interface totals.
- [NetworkStatsFactory](https://android.googlesource.com/platform/packages/modules/Connectivity/+/64cd443febd3ee0fd5c90b47089d82b96850c1e9/service-t/src/com/android/server/net/NetworkStatsFactory.java) defines interface summaries as IP-layer, boot-monotonic accounting. Link counters from `/proc/net/dev` are a transport control, not a drop-in replacement for those semantics.

Framework `NetworkManagementService` retains permission checks and its active quota/alert state. NetworkPolicyManager uses interface limits independently of UID firewall decisions. Preserve those distinctions and stock handling outside the strict container gate.

## Sampled global-alert implementation

The netd global byte-alert backend is enabled only under the existing `ROYD_CONTAINER=1` plus exact SELinux-interface `ENOENT` gate. It uses private verified interface accounting, independent of packet quotas and associated alerts. Other interfaces/environments retain stock handling.

Registration requires positive bytes through `INT64_MAX`, successful reads of the verified accounting source and successful sampler creation. It returns the actual failure without recording a new window on error. Zero and negative values fail with `ERANGE` in this backend, matching the stock diagnostic's documented positive range; the stock negative-value path outside the gate is preserved. Every successful call takes fresh RX/TX baselines and replaces the previous generation. Comparisons use separate unsigned deltas without overflowing RX+TX. Removing an absent registration retains the controller's existing `-1` result. Bandwidth reset cancels the current window.

The process-owned sampler checks nominally every 250 ms, including both directions and every UID already covered by the interface hooks. Scheduling, map reads and Binder delivery add delay; there is no hard upper delivery-latency guarantee. It never updates packet maps, modifies packets or drops traffic. Additional active non-loopback IPv4/IPv6 interfaces fail registration/sampling with `EOPNOTSUPP`, instead of presenting `eth0` totals as complete multi-interface usage. A missing interface/source, changed map/link identity, counter regression or accounting error makes the window unavailable and disarmed. Polling/delivery faults remain visible in the permission-checked netd dump and diagnostics; they do not become zero usage or successful callbacks. Sampling faults are sticky for that backend lifetime.

At crossing, the worker commits that generation's one-shot notification, releases its lock and calls the existing registered netd listeners with `onQuotaLimitReached("globalAlert", "eth0")`. An old pending read cannot commit after cancellation/replacement. A Binder call already committed before replacement may still arrive afterwards and cannot be recalled; there is no new generation token in the existing AIDL interface. No alert/controller lock is held during notification, so framework rearming can re-enter safely. Each listener is attempted once; no fabricated callback or silent retry conceals delivery failure. An empty listener list or failed transaction is logged, and a failure still belonging to the current generation faults that window. `committed` in the dump counts dispatch commitments, not confirmed framework receipt.

`dumpsys netd` reports generation, threshold, armed state, commitments, error and nominal sample interval. The bounded `ROYD: using sampled container global byte alerts` marker appears only after successful registration. There is no persistent userspace threshold or delayed event queue to resurrect after netd restart. Framework registration/rearming remains at its stock call sites; actual restart/reconnect behaviour must be witnessed on the rebuilt image. The prior private accounting maps remain independently boot-monotonic.

Run `make android15-global-alert-container-test`; set `ROYD_ANDROID15_ALERT_SOURCE=<applied-tree>` to compare the actual new headers. The executable contracts exercise exact crossing, no premature/duplicate callback, new baselines, cancellation/replacement during pending reads, callback re-entry, worker/read/source failures, identity/regression checks, overflow-safe sums, additional-interface rejection and the patched controller entry points. Existing accounting contracts cover the shared strict gate. Compilation with the actual Android netd commands is an additional source check, not a linked image or callback qualification. See [runtime validation](validation.md#sampled-global-byte-alerts) for the required rebuilt-image evidence. These global-alert contracts do not qualify byte quotas or associated interface alerts; their separate source and runtime gates are described below.

## Packet-quota source backend

Patch `0071` implements the selected `eth0` quota API only under the existing exact container/SELinux-`ENOENT` gate. The separate `roydquota.o` uses BPF ISA v3 atomic CAS and is included in the existing Tethering APEX; the stock `netd.o` target and UID policies are unchanged. Startup requires actual loaded programs/maps and two private TCX links ordered after the verified accounting links, with namespace membership and ordering checks. It never replaces qdiscs or unowned links. Invalid layouts, foreign keys or mismatching pins fail setup; kernel versions alone do not establish capability. No host module or tracing change is introduced.

One normal, non-LRU, `BPF_F_NO_PREALLOC` hash entry holds immutable limit/generation metadata and an aligned 64-bit remainder shared across ingress, egress, CPUs and all UIDs. An atomic snapshot and bounded CAS loop reserve an entire skb's independently defined IP cost, including replicated GSO/GRO headers. Exact fit passes. Insufficient allowance atomically exhausts the remainder and drops the whole skb/aggregate, discarding the unused tail; later IP packets remain denied. Accepted IP cost cannot exceed that generation's allowance. Non-IP traffic passes without charge, and loopback is outside the attached interface. Malformed/unsupported active traffic and exhausted CAS contention fail closed for that skb, with separate visible counters. A contended refusal grants no allowance and does not fabricate usage.

Control updates publish a fresh hash allocation instead of copying multiple fields over live packet state. Linux's [hash update/RCU implementation](https://github.com/torvalds/linux/blob/v6.8/kernel/bpf/hashtab.c) publishes the replacement before retiring the old entry; [atomic CAS](https://docs.kernel.org/bpf/standardization/instruction-set.html#atomic-operations) serialises reservations on each entry. A packet that already selected an old entry can finish against its old generation after an update/removal returns. It cannot debit or replenish the replacement. New lookups select the published window; no instantaneous recall of an already admitted skb is claimed. Budget/metadata reads use the real map. Positive int64 quota changes create a fresh allowance, zero/other negatives return ERANGE, `-1` removes, and removing an absent quota returns ENODEV. Failed updates retain the prior entry. Netd initialisation preserves it; explicit framework replay is a new registration, with restart behaviour still requiring runtime evidence.

Accounting executes before quota rejection, so its totals include IP attempts reaching the interface hook, including quota-rejected packets. Quota remainder is a separate admission budget, not that usage counter. Ingress charges before later socket/UID filtering; egress UID denials before TCX consume no quota, while later drops can consume reserved allowance. Root/raw/system traffic has no quota exemption. Direct Docker exec remains an independent control path when network traffic, including ADB, is capped. Interface replacement/recycled indices require a fresh instance, not adoption of stale pins.

Binder caller checks remain unchanged. Other interfaces/environments use stock code. Global alerts are independent; associated alerts use the separate admitted-byte source described below. Quota enforcement does not depend on sampler delivery.

Run `make android15-interface-quota-container-test`; set `ROYD_TEST_BPF_TREE=<applied-tree>` for real Android Clang compilation and `ROYD_ANDROID15_QUOTA_SOURCE=<applied-tree>` for byte comparisons. With sufficient local BPF permissions and at least two CPUs, run `ROYD_TEST_BPF_TREE=<tree> ROYD_QUOTA_KERNEL_OUTPUT_DIR=<new-directory> make android15-interface-quota-kernel-test`. This loads the exact Android ELF instructions, relocates only their map FDs, verifies Android map metadata and uses private unpinned maps and synthetic test-run packets. The budget test never attaches to an interface or sends packets. The additional link-query gate extracts the actual production `info`, `validLink` and `quotaLink` functions and uses owned unpinned TCX links only on loopback in a fresh private network namespace. It requires correct ordering to pass and reversed ordering to fail in both directions, then removes its links. Its name-to-FD resolver duplicates only these owned descriptors; it never accesses product pins or a live OCI interface. Boundary, malformed/L2, four-CPU shared allowance, controlled replacement and removal checks pass locally; native contracts additionally cover whole-GSO rejection, contention bounds, invalid state, link ownership/order, failed updates and stock controller preservation. Initial compiler/helper/metadata findings remain retained. These are kernel/source checks, not an Android image or real-traffic support claim. See [runtime validation](validation.md#interface-byte-quotas).

## Associated interface-alert source

Append-only patch0075 replaces the selected interface's explicit unsupported path with a sampled `eth0Alert`/`eth0` notification. It retains the exact container gate, stock netd Binder permissions and all stock bodies for other interfaces/environments. Positive thresholds require an existing healthy quota, verified private source and successfully started worker. Zero/negative thresholds return ERANGE, an absent quota returns ENOENT, and failed registration keeps the prior window. Every successful registration uses the newly requested threshold and a fresh baseline. Alert removal returns ENOENT when absent; both quota-removal APIs cancel its associated alert only after successful map deletion. Failed quota deletion preserves the prior registration.

The new private one-entry `quota_admitted` array counts IP bytes only after a complete quota reservation and successful counter update. It includes both directions, UIDs and supported aggregate header costs. Whole-packet quota drops and discarded crossing tails never become admitted usage. Packets without a registered quota pass without incrementing this counter, because no associated alert can then be armed. A bounded atomic CAS prevents counter overflow; missing state, overflow or exhausted counter contention drops the packet and latches the existing visible quota fault. A reservation already taken is not refunded if usage recording fails. This remains a fail-closed fault, not healthy measured consumption. The map is never written/reset by the controller. Old RCU-selected packets can finish after replacement/removal and still increment the same boot-monotonic source.

Accounting before the quota still measures attempts, including rejected packets. It must not be used as the associated alert's admitted-byte source. The independent global sampler retains its original accounting semantics. The packet budget ABI and enforcement arithmetic are unchanged; the extra BPF map and instructions require rebuilding the Tethering APEX as well as netd.

The interface sampler checks nominally every250ms. Scheduling, map reads and Binder delivery add unbounded notification delay; sampling never enforces a limit. Source identity includes ifindex, usage-map ID and all four accounting/quota link IDs. Disappearance, regression, quota/backend faults and failed notification are visible sticky errors, never healthy zero usage. The permission-checked dump reports the registration generation, requested threshold, armed state, dispatch commitments and error. Its bounded marker is `ROYD: using sampled container interface byte alerts`, emitted only after successful registration, not required at boot.

Sampling, successful quota removal and cancellation share the interface-alert lifecycle lock; the reader takes the existing quota mutex inside that lock. Quota updates preserve the admitted counter and alert baseline. The sampler commits one notification while holding its own lock, then releases every backend lock before notifying the existing listeners. Re-entry can register a replacement. A callback already committed before cancellation/removal may arrive afterwards because stock AIDL has no generation token; uncommitted work cannot escape successful cancellation. A failed old delivery cannot fault a newer registration. Every listener is attempted once, and an empty list or failed transaction is a visible delivery fault. The dump's commitment count is not receipt proof.

Netd lifetime owns registrations: restarting netd does not resurrect an old userspace listener. Private quota budgets and admitted counters remain preserved. The [service recovery gates](validation.md#network-backend-service-recovery) verify Binder death and explicit fresh-client re-registration; do not infer automatic listener survival or continuous restart-window enforcement.

`make android15-interface-alert-container-test` executes the actual patch-added sampler, reader and controller gates. `ROYD_ANDROID15_INTERFACE_ALERT_SOURCE=<applied-tree>` additionally compares applied headers and every changed controller method. The quota contract now tests whole-GSO admission versus discarded tails, missing usage state, non-wrapping counter updates and the additional map's required layout. Its exact Android ELF kernel gate checks real verifier/load behaviour and admitted-byte totals across four-CPU synthetic competition/replacement. These are source/component checks, not rebuilt-image callbacks or full packet acceptance. Follow [interface-alert validation](validation.md#associated-interface-alerts) before marking runtime support.

## Required implementation invariants

Under the strict gate, netd creates private pinned TCX ingress/egress links on existing `eth0`, verifies program/link/direction/current-namespace membership, then activates a private selector. It does not replace clsact qdiscs or unowned links. Links/maps/counters survive netd/framework restarts without reset. Reject mismatched/detached pins and interface replacement rather than adopting state by recycled ifindex; device replacement requires a fresh instance. Actual load/attach operations establish capability, not a kernel-version guess. Setup failure remains fatal and visible.

The hooks count IPv4/IPv6 IP lengths, excluding Ethernet headers, padding, ARP and loopback. Supported TCP/UDP GSO/GRO adds the replicated IP/transport headers using the kernel's segment count and actual IPv4/TCP header lengths, not a fixed-MTU estimate. Unsupported segmented protocols/IPv6 extension chains, malformed headers, failed packet reads or missing counter entries latch a sticky unavailable flag. They do not drop packets or masquerade as zero usage. Interface byte/packet increments are atomic across CPUs. Normal UID accounting keeps its existing independent AOSP semantics.

Ingress is measured before subsequent tc/netfilter/socket-UID policy drops; egress is measured after socket-UID denial but before subsequent tc/qdisc/driver drops. System, raw and unassociated packets reaching these hooks are not excluded by a UID firewall exemption. Selected-interface xt_bpf and legacy ingress-account actions omit only their duplicate accounting update; other interfaces and all packet-policy decisions remain unchanged. Physical CLAT semantics, forwarding, non-Ethernet/VLAN devices, IPv6-only and multi-interface operation remain outside this baseline's acceptance. Accounting begins when both verified links are activated, not at namespace creation.

The permission-checked `dumpsys netd` status requires both links attached in the current namespace, readable state and zero sticky errors. Runtime assertions require that status and the activation marker. A readable map alone is insufficient: real workloads must establish native/UID/interface progress and independent fixture receipts. Public TrafficStats total/own-UID readings provide scoped API controls without new app permissions or cache clearing; they do not qualify every interface or persisted history.

Netd's startup cleanup and physical-network lifecycle leave `eth0`'s clsact qdisc alone under the same gate, because the private links neither need nor own it. Other interfaces and stock behaviour outside the gate remain unchanged. Attachment and packet traversal follow Linux's [TCX link implementation](https://github.com/torvalds/linux/blob/v6.8/kernel/bpf/tcx.c) and [network-device hooks](https://github.com/torvalds/linux/blob/v6.8/net/core/dev.c).

The failure latch lives in a separate aligned four-byte map entry. Packet writers store only one through a volatile word access; the controller never clears or updates it. This avoids unsupported 32-bit atomic-OR compilation and activation overwriting an error. [Kernel aligned scalar/marked-access guarantees](https://docs.kernel.org/core-api/wrappers/memory-barriers.html) define that access boundary, not a multi-field budget guarantee. Contracts inject an activation-time error and require setup failure. `ROYD_TEST_BPF_TREE` adds real Android Clang BPF compilation.

Enable a replacement only with `ROYD_CONTAINER=1` and a SELinux enforcement-interface probe failing with exactly `ENOENT`. Other probe failures retain stock behaviour. Keep all maps, control state and packet attachments inside the instance's existing private BPF/cgroup/network boundaries. Do not load host modules, change host tracing/sysctl policy, create fake proc files, replace unowned filters/qdiscs or alter OCI addresses, main routes, DNS, MTU or interface provisioning.

### Accounting first

- Establish real ingress and egress IP-byte accounting for the selected interface before using its totals for notifications or quotas. Cover ordinary and system UIDs; a system-UID firewall exemption must not silently exempt traffic from interface totals or limits.
- Define packet traversal, blocked-packet ordering, segmentation/offload accounting and CLAT exclusions against the actual AOSP code. Prevent duplicate updates if legacy or tc accounting is also active. A cgroup-only counter must not be called an interface counter without proving its coverage.
- Preserve independent UID statistics, recorder behaviour and existing packet policies. Raw UID-map advancement alone does not qualify UID history or persisted usage.
- Detect unavailable maps, malformed entries, counter regression and interface disappearance/reuse. Never turn an unavailable read into measured zero use. Do not key a new device's policy solely by a recycled ifindex or silently transfer an exhausted allowance to it.

### Quotas are enforcement

Enforce the selected interface's shared RX/TX budget in the packet path. A userspace polling loop, delayed callback, logical network hiding or disabled getter is not a hard quota. Specify the treatment of the threshold-crossing packet and any permitted overshoot before claiming enforcement. Retain packet-policy ordering and prove that another CPU, UID, direction or socket cannot obtain an independent full allowance.

Shared BPF values are concurrently accessible across CPUs; [kernel map documentation](https://docs.kernel.org/bpf/map_hash.html#concurrency) describes the synchronisation boundary. A lookup followed by an unlocked decrement is insufficient. Map replacement atomicity does not itself prove an atomic multi-field budget update. Verify control-plane changes versus packet updates, integer overflow/underflow and actual verifier/helper compatibility. Do not select support by a kernel-version guess or grant additional host tracing privileges.

### Alerts are notifications

Deliver real one-shot global/interface threshold notifications with the existing framework identities and permission checks. Preserve statistics polling/rearming and provider notifications. Alerts must not themselves become packet drops. If notification delivery is sampled from a private event map, document its scheduling delay separately from in-kernel quota enforcement; do not claim instantaneous delivery.

Use generation-aware registration/removal so a delayed event cannot fire for a replacement alert. Do not issue Binder callbacks while holding a lock that callback handling may re-enter. Rearm from a defined accounting baseline, not an old pending event. Service/framework restart and interface changes must not resurrect stale notifications or silently discard a still-enforced quota.

| Operation | Required result | Failure boundary |
| --- | --- | --- |
| Install/update quota | Acknowledged packet-path budget, defined update point | Keep coherent prior state or fail closed; no successful getter-only update |
| Remove quota | Stop enforcement and remove its associated alert consistently | Do not report removal while the old limit remains active |
| Install/update interface alert | Require the existing quota and use the requested new threshold | Do not retain an old threshold as a successful update |
| Register global alert | Arm a new window and preserve provider registration | Do not record failed legacy installation as an armed replacement |
| Remove/rearm alert | Cancel stale generations; one notification for each new crossing | No duplicate, stale or fabricated notification |

Keep each API layer's existing caller checks, absence/duplicate semantics and errors. Review invalid values and legacy sentinels explicitly rather than inventing one common interpretation across quota and alert APIs. Map/open/update/attach errors must remain visible and must not acknowledge unenforced security state. Define restart ownership and rollback before wiring the new backend into service calls.
